# Fivechese项目 网络连接错误修复说明

## 错误描述

在网络对战模式下，客户端连接服务器时出现以下错误：

```
java.net.ConnectException: Connection refused: connect
         at java.base/sun.nio.ch.Net.connect0(Native Method)      
         at java.base/sun.nio.ch.Net.connect(Net.java:579)        
         at java.base/sun.nio.ch.Net.connect(Net.java:568)        
         at java.base/sun.nio.ch.NioSocketImpl.connect(NioSocketImpl.java:588) 
         at java.base/java.net.SocksSocketImpl.connect(SocksSocketImpl.java:327) 
         at java.base/java.net.Socket.connect(Socket.java:633)    
         at java.base/java.net.Socket.connect(Socket.java:583)    
         at java.base/java.net.Socket.<init>(Socket.java:507)     
         at java.base/java.net.Socket.<init>(Socket.java:287)     
         at five.edu.cn.util.NetHelper.lambda$connect$1(NetHelper.java:120)
```

---

## 错误原因分析

### 根本原因

`Connection refused: connect` 错误表示**客户端尝试连接的服务器端口没有程序在监听**。

### 可能的具体原因

| 原因 | 说明 | 概率 |
|------|------|------|
| **服务器未启动监听** | 客户端点击"连接服务器"时，服务器端没有先点击"开始监听" | ⭐⭐⭐ 高 |
| **IP地址错误** | 客户端输入了错误的IP地址 | ⭐⭐ 中 |
| **防火墙阻止** | Windows防火墙阻止了端口8900的连接 | ⭐⭐ 中 |
| **端口被占用** | 端口8900被其他程序占用 | ⭐ 低 |
| **网络不通** | 两台电脑之间网络无法连通 | ⭐ 低 |

### 最常见的操作错误

用户可能的操作流程：
1. ❌ 客户端先点击"连接服务器"
2. ❌ 然后服务器才点击"开始监听"

**正确的操作流程应该是**：
1. ✅ 服务器端先点击"开始监听"
2. ✅ 然后客户端再点击"连接服务器"

## 正确的联机操作流程

### 单机测试（同一台电脑）

需要运行两个程序实例：

#### 实例A（作为服务器）：
1. 启动程序
2. 点击"开始游戏"
3. 选择"网络对战"模式
4. 选择棋子颜色（建议黑棋）
5. 点击"开始监听"按钮
6. 等待状态显示"监听中，端口: 8900"

#### 实例B（作为客户端）：
1. 启动另一个程序实例
2. 点击"开始游戏"
3. 选择"网络对战"模式
4. 选择棋子颜色（建议白棋）
5. IP地址输入框保持 `localhost` 或输入 `127.0.0.1`
6. 点击"连接服务器"按钮
7. 等待状态显示"已连接到: localhost"

### 两台电脑联机

#### 电脑A（服务器端）：
1. 查看本机IP地址：
   - 按 `Win + R`，输入 `cmd`，回车
   - 输入 `ipconfig`，查看IPv4地址（如 `192.168.1.100`）
2. 启动程序
3. 点击"开始游戏"
4. 选择"网络对战"模式
5. 选择棋子颜色（建议黑棋）
6. 点击"开始监听"按钮
7. 等待状态显示"监听中，端口: 8900"
8. 告知电脑B你的IP地址

#### 电脑B（客户端）：
1. 启动程序
2. 点击"开始游戏"
3. 选择"网络对战"模式
4. 选择棋子颜色（建议白棋）
5. IP地址输入框输入电脑A的IP地址（如 `192.168.1.100`）
6. 点击"连接服务器"按钮
7. 等待状态显示"已连接到: 192.168.1.100"

## 常见问题排查

### 问题1：连接失败，提示"服务器未启动监听"

**解决方案**：
1. 确保服务器端先点击了"开始监听"按钮
2. 检查服务器端状态是否显示"监听中，端口: 8900"
3. 确认两台电脑在同一局域网内

### 问题2：本机测试连接失败

**解决方案**：
1. 确保运行了两个程序实例
2. 第一个实例先点击"开始监听"
3. 第二个实例再点击"连接服务器"
4. IP地址使用 `localhost` 或 `127.0.0.1`

### 问题3：防火墙阻止连接

**解决方案**：

#### 方法1：临时关闭防火墙（测试用）
```powershell
# 以管理员身份运行PowerShell
netsh advfirewall set allprofiles state off
```

#### 方法2：添加防火墙例外规则
```powershell
# 以管理员身份运行PowerShell
# 添加入站规则
netsh advfirewall firewall add rule name="Fivechese Port 8900" dir=in action=allow protocol=tcp localport=8900

# 添加出站规则
netsh advfirewall firewall add rule name="Fivechese Port 8900" dir=out action=allow protocol=tcp localport=8900
```

#### 方法3：通过图形界面设置
1. 打开"控制面板" → "系统和安全" → "Windows Defender 防火墙"
2. 点击"高级设置"
3. 点击"入站规则" → "新建规则"
4. 选择"端口" → 输入 `8900` → 选择"TCP"
5. 选择"允许连接"
6. 配置文件全部勾选
7. 名称输入 `Fivechese`，完成
8. 同样方法创建"出站规则"

### 问题4：检查端口是否被占用

```powershell
# 查看端口8900是否被占用
netstat -ano | findstr :8900

# 如果有输出，说明端口被占用，查看占用的进程ID
# 然后可以在任务管理器中结束该进程
```

### 问题5：检查网络连通性

```powershell
# 在客户端电脑上ping服务器IP
ping 192.168.1.100

# 如果ping不通，说明网络有问题
```

## 总结

### 问题本质

`Connection refused` 错误**不是代码bug**，而是**用户操作流程错误**或**网络配置问题**。

### 改进措施

1. **添加状态显示**：让用户清楚地知道当前连接状态
2. **添加详细错误提示**：连接失败时告诉用户可能的原因和解决方案
3. **添加按钮状态管理**：防止用户在错误的时机点击按钮
4. **添加工具提示**：指导用户正确操作

### 正确操作口诀

> **服务器先监听，客户端后连接**

1. 服务器：开始游戏 → 网络对战 → 选择颜色 → **开始监听**
2. 客户端：开始游戏 → 网络对战 → 选择颜色 → 输入IP → **连接服务器**
