# Fivechese 五子棋项目分析文档

## 一、项目概述

Fivechese 是一个基于 Java Swing 开发的五子棋游戏，支持本地双人对战和网络对战模式，并提供了观战功能。项目采用 MVC 架构设计，使用单例模式管理核心组件。

#### 2.1.2 核心方法

| 方法 | 功能说明 |
|------|---------|
| `putChess(row, col, color)` | 在指定位置放置棋子，返回是否成功 |
| `getChess(row, col)` | 获取指定位置的棋子颜色 |
| `judge()` | 判断胜负，返回获胜方颜色 |
| `clearchess()` | 清空棋盘 |
| `back()` | 悔棋（撤销最近两步） |

#### 2.1.3 胜负判断算法

**设计思路**：从最后落子的位置出发，向四个方向（横、竖、左斜、右斜）检查是否有连续 5 个同色棋子。

```java
public int judge() {
    int m = data[lastrow][lastcol];  // 最后落子的颜色
    int num = 1;
    
    // 1. 横向检查
    for (int i = lastcol + 1; i < width; i++) {
        if (data[lastrow][i] == m) {
            num++;
            if (num == 5) return m;
        } else break;
    }
    for (int i = lastcol - 1; i >= 0; i--) {
        if (data[lastrow][i] == m) {
            num++;
            if (num == 5) return m;
        } else break;
    }
    
    // 2. 纵向检查（类似横向）
    // 3. 左斜线检查（左上到右下）
    // 4. 右斜线检查（右上到左下）
    
    return Space;  // 无人获胜
}
```

**算法特点**：
- **高效性**：只需检查最后落子位置的四个方向，而非整个棋盘
- **正确性**：覆盖了所有可能的获胜方向
- **时间复杂度**：O(1)，最多检查 16 个位置（每个方向 4 个）

#### 2.1.4 悔棋机制

```java
public void back() {
    if (list.size() < 2) return;  // 边界检查：至少需要两步才能悔棋
    
    // 撤销最后一步（对手的棋）
    int row1 = list.getLast().row;
    int col1 = list.getLast().col;
    data[row1][col1] = Space;
    list.removeLast();
    
    // 撤销倒数第二步（自己的棋）
    int row = list.getLast().row;
    int col = list.getLast().col;
    data[row][col] = Space;
    list.removeLast();
}
```

**设计说明**：每次悔棋撤销两步，因为五子棋是轮流下的，悔棋需要同时撤销自己和对手的各一步。

### 3.2 角色分配机制

服务器按"先到先得"原则分配角色：

```

第1个连接 → 黑棋玩家（先手）
第2个连接 → 白棋玩家（后手）
第3个及以后 → 观众（可观看但不能下棋）
```

### 3.4 消息处理流程

#### 3.4.1 服务器端消息处理

```java
private void processMessage(String line) {
    if (line.startsWith("LOGIN:")) {
        // 1. 登录：分配角色
        String name = line.substring(6);
        assignRole(this, name);
    } else if (line.startsWith("PutChess:")) {
        // 2. 下棋：记录历史并广播
        if (chessHistory.isEmpty()) {
            chessHistory = line;
        } else {
            chessHistory += "|" + line;
        }
        broadcast(line);
    } else if (line.startsWith("chat")) {
        // 3. 聊天：添加用户名后广播
        String chatMsg = line.substring(4);
        String fullMsg = "CHAT:" + userName + ":" + chatMsg;
        broadcast(fullMsg);
    } else if (line.startsWith("reback")) {
        // 4. 悔棋：更新历史并广播
        broadcast(line);
        if (!chessHistory.isEmpty()) {
            int lastIndex = chessHistory.lastIndexOf("|");
            if (lastIndex > 0) {
                chessHistory = chessHistory.substring(0, lastIndex);
            } else {
                chessHistory = "";
            }
        }
    } else if (line.startsWith("CLEAR")) {
        // 5. 清空：清空历史并广播
        chessHistory = "";
        broadcast(line);
    }
}
```

### 3.5 棋局同步机制

当新观众加入房间时，需要同步当前棋局状态：

```
服务器端流程：
1. 检测到新连接
2. 分配角色为观众
3. 检查是否有历史棋局（chessHistory）
4. 如果有，发送 SYNC:历史记录

客户端流程：
1. 收到 SYNC:历史记录
2. 清空本地棋盘
3. 按顺序解析每一步棋
4. 逐一把棋子放到棋盘上
5. 重绘棋盘
```

**代码实现（NetHelper.java）**：

```java
private void parseSync(String line) {
    String history = line.substring(5);
    if (history.isEmpty()) return;
    
    // 分割历史记录
    String[] moves = history.split("\\|");
    Model.getInstance().clearchess();
    
    // 逐手下棋
    for (String move : moves) {
        if (move.startsWith("PutChess:")) {
            String data = move.substring(9);
            String[] array = data.split(",");
            int row = Integer.parseInt(array[0]);
            int col = Integer.parseInt(array[1]);
            int color = Integer.parseInt(array[2]);
            Model.getInstance().putChess(row, col, color);
        }
    }
    ChessPanel.getInstance().repaint();
}
```

## 四、安全风险分析

### 4.1 严重风险

#### 4.1.1 无身份认证机制

**问题描述**：
- 任何人都可以连接到服务器，无需用户名密码验证
- 用户名可以任意填写，没有唯一性约束
- 无法识别用户真实身份

**风险场景**：
- 恶意用户可以伪装成其他用户
- 无法追溯恶意行为的责任人
- 可以无限创建连接消耗服务器资源

**代码位置**：
- `RoomServer.java:216-218` - 仅根据用户名分配角色，无验证

```java
if (line.startsWith("LOGIN:")) {
    String name = line.substring(6);  // 直接使用，无验证
    assignRole(this, name);
}
```

**修复建议**：
- 添加用户注册/登录机制
- 使用唯一标识符（如 UUID）标识用户
- 添加连接数限制

---

#### 4.1.2 明文传输，无加密

**问题描述**：
- 所有网络通信都是明文传输
- 下棋位置、聊天内容、用户名都可以被网络嗅探
- 消息可以被中间人篡改

**风险场景**：
- 局域网内可以使用 Wireshark 等工具捕获所有通信
- 恶意用户可以伪造下棋消息
- 聊天隐私泄露

**代码位置**：
- `RoomServer.java:165-166` - 使用普通 Socket，无 SSL/TLS

```java
reader = new BufferedReader(new InputStreamReader(socket.getInputStream()));
writer = new PrintWriter(socket.getOutputStream(), true);
```

**修复建议**：
- 使用 `SSLSocket` 替代普通 `Socket`
- 配置 SSL 证书实现加密传输
- 添加消息完整性校验（如 HMAC）

---

#### 4.1.3 无输入验证，存在注入风险

**问题描述**：
- 用户名没有长度和格式限制
- 聊天消息没有任何过滤
- 下棋坐标没有严格的边界验证

**风险场景**：
- **超长用户名攻击**：发送超长用户名可能导致缓冲区溢出或内存耗尽
- **格式字符串攻击**：用户名包含特殊字符可能导致解析错误
- **聊天消息注入**：虽然是 Swing 应用，但如果消息包含特殊字符可能导致显示异常
- **坐标越界攻击**：发送无效坐标可能导致数组越界

**代码位置**：
- `NetHelper.java:34-36` - 用户名直接设置，无验证

```java
public void setUserName(String userName) {
    this.userName = userName;  // 无验证
}
```

- `RoomServer.java:226-229` - 聊天消息直接转发

```java
} else if (line.startsWith("chat")) {
    String chatMsg = line.substring(4);  // 无过滤
    String fullMsg = "CHAT:" + userName + ":" + chatMsg;
    broadcast(fullMsg);
}
```

**修复建议**：
- 限制用户名长度（如 1-20 字符）
- 过滤特殊字符或使用白名单
- 严格验证下棋坐标（0-18）
- 限制消息长度

### 4.2 中等风险

#### 4.2.4 无连接数限制，可能导致资源耗尽

**问题描述**：
- 服务器可以接受无限数量的连接
- 没有最大连接数限制
- 没有超时机制

**风险场景**：
- 恶意用户可以发起连接洪水攻击
- 创建大量连接消耗服务器内存和 CPU
- 正常用户无法连接

**代码位置**：
- `RoomServer.java:51-56` - 无限循环接受连接

**修复建议**：
- 设置最大连接数限制（如 100）
- 添加连接超时机制
- 监控连接状态，清理僵尸连接

**修复建议**：

- 添加端口占用检测
- 支持随机端口生成

#### 4.2.6 无断线重连机制

**问题描述**：
- 玩家断线后无法恢复之前的角色
- 棋局状态可能丢失
- 观众断线后需要重新同步

**风险场景**：
- 网络波动导致玩家掉线
- 无法恢复游戏进程
- 对战体验差

**代码位置**：
- `RoomServer.java:114-128` - 断线后直接移除


- 支持断线后一定时间内重连恢复角色
- 持久化棋局状态

### 4.3 低风险

#### 4.2.7 硬编码文件路径

**问题描述**：
- 图片和音乐文件使用相对路径
- 路径依赖于工作目录
- 不同操作系统路径分隔符不同

**风险场景**：
- 从不同目录启动程序可能导致资源加载失败
- Windows 和 Linux 路径分隔符问题
- 资源文件位置不可配置

**代码位置**：
- `ChessPanel.java:31` - 硬编码图片路径

```java
Image imageIcon = new ImageIcon("painting/view.jpg").getImage();
```

- `BackGroundMusic.java:18` - 硬编码音乐路径

```java
private static File file = new File("music\\bkmusic.wav");  // Windows 风格路径
```

**修复建议**：
- 使用类加载器获取资源
- 配置文件管理资源路径
- 使用 `File.separator` 或 `Paths.get()` 处理路径

#### 4.2.8 无权限控制（观众权限不足）

**问题描述**：
- 观众无法请求成为玩家
- 玩家无法主动让出位置
- 没有踢人/禁言功能

**风险场景**：
- 观众想参与对战但无法实现
- 恶意观众可以发送骚扰消息
- 房间管理能力弱

**代码位置**：
- `Control.java:108-112` - 观众无法下棋


**修复建议**：
- 添加观众请求上麦机制
- 添加玩家让渡机制
- 添加房间管理功能（踢人、禁言）

## 五、总结

### 5.1 项目优点

1. **架构清晰**：采用 MVC 模式，代码结构良好
2. **功能完整**：支持本地对战、网络对战、观战、复盘等功能
3. **多房间支持**：通过动态端口实现多个房间同时运行
4. **单例模式**：核心组件使用单例，避免重复实例化
5. **多线程处理**：网络通信使用独立线程，不阻塞 UI

### 5.2 改进建议

除了安全风险修复外，还可以考虑以下优化：

1. **UI 美化**：使用更现代的 UI 组件和主题
2. **AI 对战**：添加人机对战功能
3. **棋局保存**：支持保存和加载棋局文件
4. **房间列表**：支持查看和选择可用房间
5. **音效反馈**：下棋、获胜等场景添加音效
6. **超时机制**：添加每步棋的超时限制
