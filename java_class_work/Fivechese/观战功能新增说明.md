# Fivechese 五子棋游戏 - 观战功能新增说明

## 一、功能概述

本次为 Fivechese 五子棋项目新增了**观战功能**，支持在两个玩家对战的同时，允许其他玩家以观众身份加入房间，实时观看对战过程，并可以参与到对战玩家的聊天中。

---

## 二、架构变更

### 2.1 原有架构
原有的网络对战采用**点对点（P2P）直连模式**：
- 一个玩家作为服务端监听（`beginListen`）
- 另一个玩家作为客户端连接（`connect`）
- 仅支持 2 个玩家对战，无法支持更多连接

### 2.2 新架构
新增功能采用**房间服务器模式**：
- 引入中央房间服务器（`RoomServer`）管理所有连接
- 支持 2 个对战玩家 + N 个观众（理论上无上限）
- 所有消息通过服务器广播到所有客户端

### 3.2 RoomServer.java - 房间服务器类

**文件路径**: `src/five/edu/cn/NetHelper.java`（内部类）

**功能说明**:
中央房间服务器，负责管理所有客户端连接、分配角色、广播消息。

**核心功能**:

#### 3.2.1 端口配置
```java
public static final int PORT = 8900;  // 服务器端口
```

#### 3.2.2 连接管理
- `clients`: 所有连接的客户端列表
- `blackPlayer`: 黑棋玩家连接
- `whitePlayer`: 白棋玩家连接
- `spectators`: 观众连接列表

#### 3.2.3 角色分配机制
当新客户端连接时，服务器按以下顺序分配角色：
1. 如果黑棋位置为空 → 分配为 **黑棋玩家**
2. 如果白棋位置为空 → 分配为 **白棋玩家**
3. 两个玩家位置都满 → 分配为 **观众**

#### 3.2.4 棋局历史记录
```java
private String chessHistory = "";  // 存储棋局历史
```
- 记录所有下棋操作，用于新观众加入时同步当前棋局状态
- 格式：`PutChess:row,col|PutChess:row,col|...`

#### 3.2.5 消息处理

服务器处理以下类型的消息：

| 消息类型 | 格式 | 说明 |
|---------|------|------|
| LOGIN | `LOGIN:用户名` | 客户端登录，发送用户名 |
| PutChess | `PutChess:row,col` | 玩家下棋，同步给所有人 |
| chat | `chat消息内容` | 聊天消息，广播给所有人 |
| reback | `reback` | 悔棋请求 |
| CLEAR | `CLEAR` | 清空棋盘 |

#### 3.2.6 消息广播机制

- `broadcast(String msg)`: 广播给所有连接的客户端
- `broadcastToPlayers(String msg)`: 仅广播给两个玩家
- `broadcastUserList()`: 广播当前房间用户列表

**文件路径**: `src/five/edu/cn/NetHelper.java`

**主要改动**:


#### 4.1.2 新增方法

**创建房间**:
```java

```
- 启动 RoomServer 房间服务器
- 自动连接到 localhost
- 第一个连接的用户将成为黑棋玩家

**加入房间**:
```java
public void joinRoom(String ip, String userName)
```
- 连接到指定 IP 的房间服务器
- 根据服务器分配获得角色

**角色判断方法**:
```java
public boolean isPlayer()       // 是否是对战玩家
public boolean isSpectator()    // 是否是观众
```

**断开连接**:
```java
public void disconnect()
```
- 关闭 Socket 连接
- 如果是房间创建者，同时停止服务器

#### 4.1.3 消息接收处理

客户端接收并处理以下服务器消息：

| 消息类型 | 处理逻辑 |
|---------|---------|
| `ROLE:BLACK/WHITE/SPECTATOR` | 设置本地角色，更新UI显示 |
| `PutChess:row,col` | 在本地棋盘放置棋子 |
| `CHAT:用户名:消息` | 显示带发送者名称的聊天消息 |
| `reback` | 执行悔棋操作 |
| `USERLIST:...` | 显示当前房间用户列表 |
| `SYNC:历史记录` | 新观众加入时同步历史棋局 |
| `CLEAR` | 清空本地棋盘 |

#### 4.1.4 棋局同步机制

当新观众加入房间时：
1. 服务器检测到该客户端角色为观众
2. 服务器发送 `SYNC:` + 历史棋局记录
3. 客户端解析历史记录，逐一把棋子放到棋盘上
4. 观众即可看到当前的完整棋局状态

### 4.4 Model.java - 数据模型类（修复）

**文件路径**: `src/five/edu/cn/Model.java`

**主要改动**:

#### 4.4.1 悔棋方法安全修复
原代码在棋子数量不足时会抛出 `NoSuchElementException`，添加边界检查：

```java
public void back() {
    if(list.size() < 2) return;  // 新增边界检查
    int row1=list.getLast().row;
    int col1=list.getLast().col;
    data[row1][col1]=Space;
    list.removeLast();
    int row=list.getLast().row;
    int col=list.getLast().col;
    data[row][col]=Space;
    list.removeLast();
}
```

**修复说明**:
- 原问题：当 `list` 为空或只有1个棋子时，调用 `getLast()` 会抛出异常
- 修复后：检查棋子数量是否大于等于2，不足则直接返回

## 五、通信协议详解

### 5.1 协议格式
所有消息采用纯文本格式，以换行符 `\n` 结尾。

### 5.2 客户端 → 服务器消息

| 命令 | 格式示例 | 说明 |
|------|---------|------|
| 登录 | `LOGIN:张三` | 客户端连接后发送用户名 |
| 下棋 | `PutChess:5,6` | 玩家在第5行第6列下棋 |
| 聊天 | `chat你好！` | 发送聊天消息 |
| 悔棋 | `reback` | 请求悔棋（每次悔2步） |
| 清空 | `CLEAR` | 清空棋盘 |

### 5.3 服务器 → 客户端消息

| 命令 | 格式示例 | 说明 |
|------|---------|------|
| 角色分配 | `ROLE:BLACK` | 分配黑棋玩家角色 |
| 角色分配 | `ROLE:WHITE` | 分配白棋玩家角色 |
| 角色分配 | `ROLE:SPECTATOR` | 分配观众角色 |
| 同步下棋 | `PutChess:5,6` | 广播某玩家的下棋位置 |
| 聊天消息 | `CHAT:张三:你好！` | 带用户名的聊天消息 |
| 用户列表 | `USERLIST:BLACK=张三;WHITE=李四;SPECTATOR=王五;` | 当前房间所有用户 |
| 棋局同步 | `SYNC:PutChess:5,6\|PutChess:5,7` | 新观众加入时同步历史 |
| 悔棋 | `reback` | 广播悔棋操作 |
| 清空 | `CLEAR` | 广播清空棋盘操作 |

### 5.4 用户列表格式
`USERLIST:` 后跟随多个键值对，用分号分隔：
- `BLACK=用户名`: 黑棋玩家
- `WHITE=用户名`: 白棋玩家
- `SPECTATOR=用户名`: 观众（可多个）

示例：
```
USERLIST:BLACK=小明;WHITE=小红;SPECTATOR=小刚;SPECTATOR=小丽;
```

## 六、使用说明

### 6.1 场景一：创建房间（作为第一个玩家）

1. 启动游戏程序
2. 在顶部网络面板中：
   - 输入用户名（或使用默认生成的）
   - 点击 **"创建房间"** 按钮
3. 系统会自动：
   - 启动房间服务器
   - 连接到本地服务器
   - 分配角色为 **黑棋玩家**（先手）
4. 等待其他玩家/观众加入

### 6.2 场景二：加入房间（作为第二个玩家）

1. 启动游戏程序
2. 在顶部网络面板中：
   - 输入用户名
   - 输入房间创建者的 **IP 地址**（如 `192.168.1.100`，本地测试用 `localhost`）
   - 点击 **"加入房间"** 按钮
3. 系统会自动：
   - 连接到指定服务器
   - 分配角色为 **白棋玩家**（后手）
4. 可以开始对战

### 6.3 场景三：加入房间（作为观众）

1. 启动游戏程序
2. 在顶部网络面板中：
   - 输入用户名
   - 输入房间服务器的 **IP 地址**
   - 点击 **"加入房间"** 按钮
3. 当两个玩家位置已满时：
   - 系统自动分配角色为 **观众**
   - 自动同步当前棋局状态
4. 作为观众：
   - ✅ 可以实时观看两位玩家的对战
   - ✅ 可以在聊天区发送消息，与所有人交流
   - ❌ 无法在棋盘上下棋
   - ❌ 无法执行悔棋操作

### 6.4 聊天功能

所有房间内的用户（包括玩家和观众）都可以参与聊天：

1. 在右侧聊天面板的 **"请输入信息"** 文本框中输入消息
2. 点击 **"发送"** 按钮
3. 消息会广播给房间内所有人
4. 聊天消息格式：
   - 自己发送：`[我]: 消息内容`
   - 他人发送：`[用户名]: 消息内容`

## 八、技术要点总结

### 8.1 单例模式
所有核心类都采用单例模式：
- `NetHelper.getInstance()`
- `Control.getInstance()`
- `Model.getInstance()`
- `ChessPanel.getInstance()`
- `Chatpanl.getInstance()`
- `NetPanel.getInstance()`
- `RoomServer.getInstance()`

### 8.2 多线程处理
- 服务器监听：独立线程
- 每个客户端连接：独立线程处理消息
- 消息读取：独立线程，避免阻塞UI
- 消息发送：独立线程，避免阻塞当前操作

### 8.3 棋局同步
新观众加入时，服务器发送历史记录，客户端按顺序重放：
```java
// 服务器端
if (角色是观众 && 有历史记录) {
    handler.sendMsg("SYNC:" + chessHistory);
}

// 客户端解析
String[] moves = history.split("\\|");
for (String move : moves) {
    // 解析 PutChess:row,col
    // 调用 Model.putChess()
}
```

### 8.4 颜色判定
网络模式下，根据已下棋子数量判定颜色：
```java
int color = (Model.list.size() % 2 == 0) ? Model.Black : Model.white;
```
- 第 0、2、4... 步：黑棋（偶数）
- 第 1、3、5... 步：白棋（奇数）

## 十、注意事项

1. **防火墙设置**: 房间服务器使用端口 8900，确保防火墙开放该端口
2. **本地测试**: 同一台电脑测试时，一个程序点击"创建房间"，其他程序用 `localhost` 或 `127.0.0.1` 连接
3. **局域网测试**: 房间创建者需要告知其他用户自己的局域网 IP 地址
4. **角色分配**: 角色由服务器自动分配，先到先得（黑棋→白棋→观众）
5. **棋局同步**: 观众加入时会自动同步当前棋局，但聊天历史不会同步
