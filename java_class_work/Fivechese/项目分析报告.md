# Fivechese 五子棋项目分析报告

## 一、项目概述

本项目是一个基于Java Swing开发的五子棋游戏，支持单机模式和网络对战模式。项目采用MVC架构设计，包含完整的游戏逻辑、图形界面、网络通信和聊天功能。

---

### 3.2 核心算法

#### 3.2.1 胜负判定算法 (`Model.java:40-92`)

**算法思路**：从最后一步落子位置出发，向四个方向（水平、垂直、左斜、右斜）检查是否有连续5个同色棋子。

**具体实现**：
1. **水平方向**：向左、向右检查连续同色棋子
2. **垂直方向**：向上、向下检查连续同色棋子
3. **左斜方向**：向左上、向右下检查连续同色棋子
4. **右斜方向**：向左下、向右上检查连续同色棋子

**时间复杂度**：O(1)（每个方向最多检查4步）
**空间复杂度**：O(1)

```java
// 胜负判定核心代码
public int judge() {
    int m = data[lastrow][lastcol];
    int num = 1;
    
    // 水平方向检查
    for (int i = lastcol + 1; i < width; i++) {
        if (data[lastrow][i] == m) { num++; if (num == 5) return m; }
        else break;
    }
    // ... 其他三个方向类似
}
```

#### 3.2.2 落子验证算法 (`Model.java:26-34`)

```java
public boolean putChess(int row, int col, int color) {
    if (row > width || row < 0 || col < 0 || col > width || data[row][col] != Space)
        return false;
    else {
        data[row][col] = color;
        list.add(new Chess(row, col, color));
        lastrow = row;
        lastcol = col;
        return true;
    }
}
```

#### 3.2.3 悔棋算法 (`Model.java:98-106`)

```java
public void back() {
    int row1 = list.getLast().row;
    int col1 = list.getLast().col;
    data[row1][col1] = Space;
    list.removeLast();
    int row = list.getLast().row;
    int col = list.getLast().col;
    data[row][col] = Space;
    list.removeLast();
}
```
**注意**：此实现每次悔棋会移除两步棋（双方各一步），适用于网络对战场景。

#### 3.2.4 坐标映射算法 (`ChessPanel.java:139-145`)

将鼠标点击坐标转换为棋盘坐标：
```java
int colmod = (e.getX() - lx) % unit;
int rowmod = (e.getY() - ly) % unit;
if (colmod > unit / 2) { col = ((e.getX() - lx) / unit) + 1; }
else col = (e.getX() - lx) / unit;
```

## 四、联网模块实现

### 4.1 网络架构

本项目采用**TCP协议**实现网络通信，支持两种模式：
1. **服务端模式**：监听端口，等待客户端连接
2. **客户端模式**：连接到指定服务器

### 4.2 核心网络类 (`NetHelper.java`)

#### 4.2.1 关键参数
```java
public static final int PORT = 8900;  // 固定端口号
private Socket s;                       // Socket连接
private BufferedReader reader;          // 输入流
private PrintWriter out;                // 输出流（自动刷新）
```

#### 4.2.2 服务端启动流程
```java
public void beginListen() {
    new Thread() {
        public void run() {
            try {
                ServerSocket ss = new ServerSocket(PORT);
                s = ss.accept();  // 阻塞等待连接
                reader = new BufferedReader(new InputStreamReader(s.getInputStream()));
                out = new PrintWriter(s.getOutputStream(), true);
                startReadThread();  // 启动读取线程
            } catch (IOException e) {
                e.printStackTrace();
            }
        }
    }.start();
}
```

#### 4.2.3 客户端连接流程
```java
public void connect(String ip) {
    try {
        s = new Socket(ip, PORT);
        reader = new BufferedReader(new InputStreamReader(s.getInputStream()));
        out = new PrintWriter(s.getOutputStream(), true);
        startReadThread();
    } catch (UnknownHostException e) {
        e.printStackTrace();
    } catch (IOException e) {
        e.printStackTrace();
    }
}
```

## 五、STRIDE安全风险评估

### 5.1 STRIDE模型简介

STRIDE是微软提出的安全威胁建模方法，包含6种威胁类型：
- **S**poofing（欺骗）
- **T**ampering（篡改）
- **R**epudiation（否认）
- **I**nformation Disclosure（信息泄露）
- **D**enial of Service（拒绝服务）
- **E**levation of Privilege（权限提升）

### 5.2 详细风险评估

#### 5.2.1 Spoofing（欺骗）

| 风险项 | 风险等级 | 说明 |
|-------|---------|------|
| 身份伪造 | 🔴 高 | 无身份验证机制，任何人都可以连接并冒充对手 |
| IP地址欺骗 | 🟡 中 | 无IP白名单或验证，易被伪造IP连接 |
| 消息发送者伪造 | 🔴 高 | 消息中不包含发送者身份标识 |

**分析**：
- 项目无任何身份认证机制，服务端接受任意客户端连接
- 消息协议中不包含发送者信息，无法验证消息来源
- 攻击者可冒充对手发送假消息（如假的悔棋请求）

#### 5.2.2 Tampering（篡改）

| 风险项 | 风险等级 | 说明 |
|-------|---------|------|
| 消息篡改 | 🔴 高 | 无消息完整性校验，消息可被中间人篡改 |
| 棋盘状态篡改 | 🔴 高 | 攻击者可发送任意位置的落子消息 |
| 聊天内容篡改 | 🟡 中 | 聊天消息无签名，可被篡改 |

**分析**：
- 无消息加密或哈希校验，TCP明文传输易被篡改
- 攻击者可修改`PutChess`消息中的坐标，在任意位置落子
- 无消息序号或时间戳，无法检测重放攻击

#### 5.2.3 Repudiation（否认）

| 风险项 | 风险等级 | 说明 |
|-------|---------|------|
| 落子行为否认 | 🔴 高 | 无不可否认机制，对方可否认落子 |
| 悔棋行为否认 | 🔴 高 | 无日志记录，可否认发送过悔棋请求 |
| 聊天消息否认 | 🟡 中 | 无消息签名，可否认发送过聊天内容 |

**分析**：
- 无数字签名或消息认证码(MAC)
- 无通信日志持久化存储
- 双方均可否认自己的行为

#### 5.2.4 Information Disclosure（信息泄露）

| 风险项 | 风险等级 | 说明 |
|-------|---------|------|
| 聊天内容泄露 | 🟡 中 | 聊天消息明文传输，易被窃听 |
| 游戏状态泄露 | 🟢 低 | 棋盘状态本身是公开信息 |
| IP地址泄露 | 🟡 中 | 连接时暴露IP地址 |

**分析**：
- 聊天消息以明文形式通过TCP传输
- 无TLS/SSL加密，网络嗅探可获取聊天内容
- 棋盘状态在游戏中是公开的，此风险较低

#### 5.2.5 Denial of Service（拒绝服务）

| 风险项 | 风险等级 | 说明 |
|-------|---------|------|
| 端口耗尽攻击 | 🟡 中 | 无连接数限制，可被大量连接耗尽资源 |
| 消息洪水攻击 | 🟡 中 | 可发送大量消息占用带宽和CPU |
| 无效消息攻击 | 🟡 中 | 可发送畸形消息导致程序异常 |

**分析**：
- 服务端无连接数限制
- 无消息频率限制，可被洪水攻击
- 消息解析缺乏异常处理，可能导致崩溃

#### 5.2.6 Elevation of Privilege（权限提升）

| 风险项 | 风险等级 | 说明 |
|-------|---------|------|
| 无权限提升风险 | 🟢 低 | 程序无权限模型，无文件系统访问 |

**分析**：
- 程序运行在普通用户权限下
- 无敏感操作或系统调用
- 此风险基本不存在

### 5.3 风险优先级总结

| 威胁类型 | 风险等级 | 优先级 |
|---------|---------|--------|
| Spoofing | 🔴 高 | P0 |
| Tampering | 🔴 高 | P0 |
| Repudiation | 🔴 高 | P0 |
| Information Disclosure | 🟡 中 | P1 |
| Denial of Service | 🟡 中 | P1 |
| Elevation of Privilege | 🟢 低 | P2 |

## 六、安全改进建议

### 6.1 高优先级改进（P0）

1. **添加身份认证**
   - 实现简单的密码验证机制
   - 或使用预共享密钥(PSK)进行身份验证

2. **添加消息完整性校验**
   - 为每条消息添加哈希值或HMAC
   - 验证消息未被篡改

3. **添加消息序号**
   - 防止重放攻击
   - 确保消息顺序

### 6.2 中优先级改进（P1）

1. **启用TLS/SSL加密**
   - 使用SSL/TLS加密TCP连接
   - 防止网络窃听

2. **添加连接限制**
   - 限制最大连接数
   - 添加消息频率限制

3. **添加日志记录**
   - 记录所有游戏事件
   - 便于事后追溯

### 6.3 低优先级改进（P2）

1. **输入验证**
   - 验证坐标范围
   - 过滤无效消息

2. **异常处理**
   - 完善异常捕获
   - 提高程序稳定性

## 八、总结

本项目是一个功能完整的五子棋游戏，采用Java Swing开发，支持网络对战。从功能角度看，项目实现了所有核心需求；但从安全角度看，存在多个高风险安全问题，主要集中在网络通信的身份认证、消息完整性和不可否认性方面。建议在实际使用前进行安全加固。
