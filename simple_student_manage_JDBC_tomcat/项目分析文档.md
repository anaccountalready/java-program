## 一、项目概述

### 1.1 项目简介
`simple_student_manage_JDBC_tomcat` 是一个基于 Java Web 技术栈开发的学生管理系统。该系统采用传统的 JSP + Servlet + JDBC 架构，实现了学生信息的增删改查、成绩管理、班级信息查看等基本功能。

### 1.2 技术栈
- **前端技术**: JSP, JSTL, HTML, CSS, JavaScript, jQuery
- **后端技术**: Java Servlet, JDBC
- **服务器**: Apache Tomcat 9.0
- **数据库**: MySQL 8.0+
- **第三方库**: mysql-connector-j-8.0.32, taglibs-standard-1.2.5

### 3.5 删除学生模块 - delstuServelet.java

**文件路径**: `src/main/java/cn/nankai/edu/cn/delstuServelet.java`

#### 存储过程调用（第33-55行）

```java
protected void doGet(HttpServletRequest request, HttpServletResponse response) 
        throws ServletException, IOException {
    String id=request.getParameter("stu_id");
    JDBCemo.getInstence();
    
    // 调用MySQL存储过程
    String sql="{call delstu(?,?)}";
    CallableStatement callstate;
    try {
        callstate = JDBCemo.connection.prepareCall(sql);
        callstate.setInt(1, Integer.valueOf(id));  // 设置输入参数
        callstate.registerOutParameter(2, java.sql.Types.INTEGER);  // 注册输出参数
        callstate.execute();
        int output=callstate.getInt(2);  // 获取输出参数
        request.getSession().setAttribute("t_error", output);
    } catch (SQLException e) { ... }
    
    JDBCemo.destroy();
    response.sendRedirect("del_stu.jsp");
}
```

**特点**: 该模块使用了 `CallableStatement` 调用存储过程，相比直接拼接SQL更安全。

## 四、安全风险分析

### 4.1 SQL注入风险 ⚠️ 高风险

#### 风险位置和分析

**1. JDBCemo.java - 核心数据库操作类**

**位置**: `JDBCemo.java:86-103` (insert方法)

```java
protected static int insert(String tables,String columns,String values) {
    // 直接字符串拼接，无任何防护
    String sql = new String("insert into " + tables +"("+columns+")values("+values+");");
    count = statement.executeUpdate(sql);
}
```

**攻击示例**:
如果攻击者在 `tea` 参数输入：
```
' OR '1'='1'; DROP TABLE student; --
```

可能导致的数据表被删除。

**类似问题的方法**:
- `update()` - 第104-116行
- `select()` - 第117-135行
- `delete_stucourse()` - 第137-151行

**2. AddstudentServlet.java**

**位置**: `AddstudentServlet.java:46-47`

```java

String sql2="select id from teacher where name="+"'"+tea+"'"+";";
```

**3. show_stuServlet.java**

**位置**: `show_stuServlet.java:65-78`


#### 修复建议

使用 **PreparedStatement** 替代 Statement 进行参数化查询：

```java
// 错误做法
String sql = "SELECT * FROM student WHERE name='" + name + "'";
statement.executeQuery(sql);

// 正确做法
String sql = "SELECT * FROM student WHERE name=?";
PreparedStatement pstmt = connection.prepareStatement(sql);
pstmt.setString(1, name);
ResultSet rs = pstmt.executeQuery();
```

```java
    String password=request.getParameter("password");
    
    // 只检查非空，不验证数据库
    if(username==null||username=="") { ... }
    if(password==null||password=="") { ... }
    
    // 直接存入会话，视为登录成功
    request.getSession().setAttribute("username", username);
    request.getSession().setAttribute("password", password);
    response.sendRedirect("index.jsp");
}
```

#### 风险分析

- **任何人**只要输入非空的用户名和密码就可以登录系统
- 没有查询数据库验证用户凭据
- 没有密码加密（虽然这里连验证都没有）

#### 修复建议

1. 查询数据库验证用户存在性
2. 密码应该使用哈希存储（如BCrypt、SHA-256）
3. 添加登录失败次数限制，防止暴力破解

---

### 4.3 会话管理缺陷 ⚠️ 中高风险

#### 风险位置

**所有Servlet和JSP页面**

#### 问题分析

1. **无会话验证**: 除了 `index.jsp` 有简单检查外，其他业务页面（如 `show_stu.jsp`, `addStudent.jsp` 等）**没有验证用户是否登录**。

   攻击者可以直接访问：
   ```
   http://localhost:8080/Student/show_stu.jsp
   ```
   无需登录即可访问所有功能。

2. **密码明文存储在Session**: `LoginAdminServlet.java:47`

   ```java
   request.getSession().setAttribute("password", password);
   ```
   密码以明文形式存储在会话中。

3. **无会话超时**: 没有配置合理的会话超时时间。

#### 修复建议

1. 使用 **Filter** 统一进行登录验证
2. 不要在Session中存储密码
3. 配置合理的会话超时（如30分钟）

---

### 4.4 敏感信息泄露 ⚠️ 高风险

#### 风险位置

**JDBCemo.java:25-27**

```java
String url = "jdbc:mysql://localhost:3306/myc_test?useUnicode=true&characterEncoding=utf8&useSSL=true";
String username="root";
String password="MsQ3Ly%sy";  // 硬编码的数据库密码
```

#### 风险分析

1. **数据库凭据硬编码**: 用户名和密码直接写在源代码中
2. **使用root用户**: 数据库连接使用超级用户 `root`，权限过大
3. **密码明文**: 密码没有加密或混淆

如果源代码泄露，攻击者可以直接获取数据库访问权限。

#### 修复建议

1. 使用 **配置文件**（如 `properties` 文件）存储敏感信息
2. 配置文件应该放在 `WEB-INF` 目录下，防止直接访问
3. 使用 **加密的配置值** 或环境变量
4. 创建专用的数据库用户，只授予必要的权限

**示例修复**:

```java
// 从配置文件读取
Properties props = new Properties();
props.load(getClass().getResourceAsStream("/db.properties"));
String url = props.getProperty("db.url");
String username = props.getProperty("db.username");
String password = decrypt(props.getProperty("db.password"));
```

### 4.5 跨站脚本攻击 (XSS) 风险 ⚠️ 中风险

#### 风险位置

**多个JSP页面**

例如 `show_stu.jsp:57-69`:

```jsp
<c:forEach begin="0" end="${countstu }" items ="${student}" var="stu">
<tr>
<td>${stu.id}</td>
<td> ${stu.name }</td>
<td> ${stu.sex }</td>
<!-- 直接输出，未转义 -->
</tr>
</c:forEach>
```

#### 风险分析

如果用户在添加学生时，在姓名中输入：
```
<script>alert('XSS')</script>
```

当其他用户查看学生列表时，脚本会在浏览器中执行。

#### 修复建议

1. 使用JSTL的 `<c:out>` 标签自动转义
2. 或者在输出时使用 `fn:escapeXml()`

```jsp
<!-- 修复方式 -->
<td><c:out value="${stu.name}" /></td>
<!-- 或 -->
<td>${fn:escapeXml(stu.name)}</td>
```

### 4.6 越权访问风险 ⚠️ 高风险

#### 风险位置

**所有业务功能**

#### 问题分析

系统 **没有任何权限控制机制**：
- 没有角色区分（管理员、普通用户）
- 没有资源访问控制
- 任何人登录后可以执行所有操作（添加、删除、修改）

#### 修复建议

1. 实现基于角色的访问控制（RBAC）
2. 敏感操作（如删除）需要二次确认或特殊权限
3. 添加操作日志记录

---

### 4.7 数据验证缺失 ⚠️ 中风险

#### 风险位置

**多个Servlet**

#### 问题分析

1. **参数类型验证缺失**:
   - 学号应该是整数，但 `delstuServelet.java:35` 直接使用：
     ```java
     String id=request.getParameter("stu_id");
     callstate.setInt(1, Integer.valueOf(id));  // 如果不是数字会抛异常
     ```

2. **长度限制缺失**: 没有对输入参数进行长度验证

3. **格式验证缺失**: 没有验证日期格式、邮箱格式等

#### 修复建议

1. 使用 `try-catch` 处理类型转换
2. 对所有输入参数进行合法性验证
3. 使用正则表达式验证格式

---

### 4.8 资源管理问题 ⚠️ 中风险

#### 风险位置

**JDBCemo.java**

#### 问题分析

1. **单例模式的连接共享**: 所有用户共享同一个数据库连接，在高并发下会出现问题

2. **ResultSet 静态存储**:
   ```java
   protected static ResultSet resulSet=null;  // 第15行
   ```
   静态的 ResultSet 会导致并发访问时的数据混乱。

3. **连接池缺失**: 没有使用数据库连接池，每次操作都创建新连接（虽然单例，但频繁开关）

#### 修复建议

1. 使用 **数据库连接池**（如 HikariCP、Druid）
2. 不要使用静态变量存储连接和结果集
3. 确保资源在finally块中关闭

## 五、代码质量问题

### 5.1 命名不规范

## 七、总结

`simple_student_manage_JDBC_tomcat` 是一个典型的 **Java Web 初学者项目**，展示了 JSP + Servlet + JDBC 的基本用法。项目实现了学生管理的基本功能，但存在 **严重的安全漏洞** 和代码质量问题。

### 主要优点

1. 功能完整：实现了增删改查的基本需求
2. 事务处理：在 `DelscoreServlet` 中正确使用了数据库事务
3. 存储过程：`delstuServelet` 正确使用了 `CallableStatement`

### 主要缺点

1. **安全问题严重**: SQL注入、认证绕过、敏感信息泄露
2. **代码质量较差**: 命名不规范、硬编码、异常处理不当
3. **架构设计简单**: 没有分层设计、没有连接池、单例模式滥用

### 学习价值

该项目非常适合作为 **安全审计的反面教材**，可以帮助开发者理解：
- 什么是SQL注入以及如何防范
- 正确的认证机制应该如何实现
- 敏感信息应该如何存储
- 安全编码的最佳实践
