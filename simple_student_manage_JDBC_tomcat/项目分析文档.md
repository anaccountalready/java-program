# simple_student_manage_JDBC_tomcat 项目分析文档

## 一、项目概述

### 1.1 项目简介
这是一个基于Java Web技术栈开发的学生管理系统，采用Servlet + JSP + JDBC的经典架构，部署在Tomcat服务器上，使用MySQL数据库存储数据。该系统提供了学生信息管理、成绩管理等核心功能，是一个典型的Java Web入门级项目。

### 1.2 技术栈
- **后端技术**：Java Servlet 4.0
- **前端技术**：JSP (JavaServer Pages) + CSS
- **数据库连接**：JDBC (Java Database Connectivity)
- **服务器**：Apache Tomcat 9.0
- **数据库**：MySQL 8.0
- **辅助库**：JSTL (JavaServer Pages Standard Tag Library)

### 1.3 项目结构
```
simple_student_manage_JDBC_tomcat/
├── Servers/                          # Tomcat服务器配置
│   └── Tomcat v9.0 Server at localhost-config/
└── Student/                          # 主项目目录

    │   └── classes/                  # 编译后的class文件

```

## 二、架构分析

### 2.1 整体架构
该项目采用了经典的**MVC (Model-View-Controller)** 架构模式，但实现相对简化：

| 架构层 | 对应组件 | 职责描述 |
|--------|---------|---------|
| **Controller (控制器)** | Servlet类 | 处理HTTP请求，协调业务逻辑，控制页面跳转 |
| **View (视图)** | JSP页面 | 展示数据，接收用户输入 |
| **Model (模型)** | JavaBean类 | 封装数据，提供数据访问方法 |
| **数据访问层** | JDBCemo类 | 封装数据库连接和操作 |

### 2.2 核心组件分析

#### 2.2.1 控制器层 (Controller)
项目中包含多个Servlet类，每个Servlet负责处理特定的业务请求：

1. **LoginAdminServlet** (`@WebServlet("/login")`)
   - 处理用户登录请求
   - 验证用户名和密码的基本格式
   - 管理用户会话

2. **AddstudentServlet** (`@WebServlet("/add")`)
   - 处理添加学生信息的请求
   - 从请求参数中获取学生信息
   - 调用数据访问层执行插入操作

3. **show_stuServlet** (`@WebServlet("/show_stu")`)
   - 处理查询学生信息的请求
   - 支持多条件组合查询
   - 将查询结果存储到会话中供JSP页面展示

4. **Show_scoreServlet** (`@WebServlet("/Show_score")`)
   - 处理查询学生成绩的请求
   - 支持按学号、分数范围查询
   - 从视图`v_stu_avgscore`中获取平均成绩

5. **delstuServelet** (`@WebServlet("/delstu")`)
   - 处理删除学生的请求
   - 使用存储过程执行删除操作
   - 处理删除结果并返回错误信息

6. **DelscoreServlet** (`@WebServlet("/DelScore")`)
   - 处理删除成绩的请求
   - 支持批量删除操作

7. **Show_claServlet** (`@WebServlet("/show_cla")`)
   - 处理查询班级信息的请求

#### 2.2.2 模型层 (Model)
项目中定义了多个JavaBean类，用于封装数据：

1. **Student类**
   - 封装学生基本信息
   - 包含属性：id, name, sex, indate, claname, major, teacher

2. **Avg_score类**
   - 封装学生平均成绩信息
   - 包含属性：stu_id, avg_score

3. **Classinfo类**
   - 封装班级信息

4. **Stuscore类**
   - 封装学生成绩信息

#### 2.2.3 数据访问层 (Data Access Layer)
**JDBCemo类**是项目的核心数据访问组件，采用单例模式实现：

- **单例模式**：通过`getInstence()`方法获取唯一实例
- **数据库连接**：在构造函数中建立与MySQL数据库的连接
- **CRUD操作**：提供了insert、update、select、delete等方法
- **资源管理**：提供destroy()方法关闭数据库连接

### 2.3 数据流分析
1. **用户请求流程**：
   ```
   用户 → JSP页面 → Servlet控制器 → JDBCemo → 数据库
   ```

2. **数据返回流程**：
   ```
   数据库 → JDBCemo → JavaBean → HttpSession → JSP页面 → 用户
   ```

3. **页面跳转机制**：
   - 主要使用`response.sendRedirect()`进行重定向
   - 通过`HttpSession`传递数据

## 三、主要实现部分逻辑分析

### 3.1 数据库连接管理
**JDBCemo类**的核心实现：

```java
// 单例模式实现
public static JDBCemo getInstence() {
    if(instance==null) {instance=new JDBCemo();}
    return instance;
}

// 数据库连接配置（硬编码）
private JDBCemo() {
    String url = "jdbc:mysql://localhost:3306/myc_test?useUnicode=true&characterEncoding=utf8&useSSL=true";
    String username="root";
    String password="MsQ3Ly%sy";
    // 注册驱动并建立连接
    Class.forName("com.mysql.jdbc.Driver");
    connection=DriverManager.getConnection(url,username,password);
    statement=connection.createStatement();
}
```

**分析**：
- 采用单例模式确保只有一个数据库连接实例
- 数据库配置信息硬编码在代码中（存在安全风险）
- 使用`DriverManager`而非连接池（性能较差）
- 创建`Statement`而非`PreparedStatement`（存在SQL注入风险）

### 3.2 用户登录逻辑
**LoginAdminServlet类**的实现：

```java
protected void doGet(HttpServletRequest request, HttpServletResponse response) {
    String username=request.getParameter("username");
    String password=request.getParameter("password");
    
    // 简单的非空检查
    if(username==null||username=="") {
        request.getSession().setAttribute("msg","请输入用户名");
        response.sendRedirect("login.jsp");
        return;
    }
    if(password==null||password=="") {
        request.getSession().setAttribute("pwd","请输入密码");
        response.sendRedirect("login.jsp");
        return;
    }
    
    // 直接存储到会话，无实际验证
    request.getSession().setAttribute("username", username);
    request.getSession().setAttribute("password", password);
    response.sendRedirect("index.jsp");
    return;
}
```

**分析**：
- 登录逻辑非常简单，只做了非空检查
- **没有实际的身份验证**（没有查询数据库验证用户名和密码）
- **密码以明文形式存储在会话中**
- 任何非空的用户名和密码都能"登录成功"

### 3.4 查询学生逻辑
**show_stuServlet类**的实现：

```java
protected void doGet(HttpServletRequest request, HttpServletResponse response) {
    // 构建查询条件
    String condition=null;
    String claname=request.getParameter("class");
    String sex=request.getParameter("sex");
    String tea=request.getParameter("tea");

    // 拼接条件字符串
    if(claname==null)cc="";

    // ... 其他条件拼接
    
    condition=cc+cm+cs+ct+ci;

    JDBCemo.select("*", "student", condition);
    
    // 处理结果集
    Student[] stu = new Student[100];
    while(JDBCemo.resulSet.next()) {
        stu[i]=new Student(...);

```

**分析**：
- **多条件组合查询**，支持按班级、性别、教师、学号、专业查询
- **条件拼接存在SQL注入风险**
- 结果集处理使用固定大小数组（100个元素），可能导致数组越界
- **N+1查询问题**：先查询学生列表，再逐个查询教师和专业名称，性能较差
- 没有使用JOIN查询优化

### 3.5 删除学生逻辑
**delstuServelet类**的实现：

```java
protected void doGet(HttpServletRequest request, HttpServletResponse response) {
    String id=request.getParameter("stu_id");
    JDBCemo.getInstence();
    
    // 使用存储过程
    String sql="{call delstu(?,?)}";
    CallableStatement callstate;
    try {
        callstate = JDBCemo.connection.prepareCall(sql);
        callstate.setInt(1, Integer.valueOf(id));
        // 注册输出参数
        callstate.registerOutParameter(2, java.sql.Types.INTEGER);
        callstate.execute();
        int output=callstate.getInt(2);
        request.getSession().setAttribute("t_error", output);
    } catch (SQLException e) {
        e.printStackTrace();
    }
}
```

**分析**：
- 使用**存储过程**执行删除操作，相对安全
- 使用`CallableStatement`，一定程度上防止SQL注入
- 但输入参数`id`没有验证，直接转换为Integer，可能抛出异常
- 没有错误处理，仅打印堆栈跟踪

## 四、安全风险分析

### 4.1 严重安全漏洞

#### 4.1.1 SQL注入漏洞
**风险等级**：⭐⭐⭐⭐⭐ (严重)

**存在位置**：
- `JDBCemo.java`中的所有数据库操作方法
- `AddstudentServlet.java`
- `show_stuServlet.java`
- `Show_scoreServlet.java`

**漏洞示例**：
```java
// 示例1：AddstudentServlet中的SQL拼接
String sql1="select id from major where name="+"'"+major+"'"+";";

// 示例2：show_stuServlet中的条件拼接
if(claname==null)cc="";
else cc=" claname="+"'"+claname+"'"+" and ";
```

**攻击场景**：
如果用户在"专业"字段输入：
```
计算机' OR '1'='1
```
则实际执行的SQL变为：
```sql
select id from major where name='计算机' OR '1'='1';
```
这将返回所有专业记录，甚至可能执行更危险的操作。

**根本原因**：
- 使用`Statement`而非`PreparedStatement`
- SQL语句通过字符串拼接构建
- 没有对用户输入进行过滤或转义

#### 4.1.2 身份验证缺失
**风险等级**：⭐⭐⭐⭐⭐ (严重)

**存在位置**：
- `LoginAdminServlet.java`

**漏洞分析**：
```java
// 代码中没有实际的身份验证逻辑
// 任何非空的用户名和密码都能"登录成功"
request.getSession().setAttribute("username", username);
request.getSession().setAttribute("password", password);
response.sendRedirect("index.jsp");
```

**攻击场景**：
- 攻击者只需在登录表单输入任意非空的用户名和密码即可进入系统
- 系统没有对用户身份进行任何验证

#### 4.1.3 敏感信息明文存储
**风险等级**：⭐⭐⭐⭐ (高危)

**存在位置**：
- `LoginAdminServlet.java`
- `JDBCemo.java`

**漏洞分析**：
1. **密码明文存储在会话中**：
```java
request.getSession().setAttribute("password", password);
```
密码以明文形式存储在HttpSession中，可能被日志记录或会话劫持获取。

2. **数据库凭据硬编码**：
```java
String url = "jdbc:mysql://localhost:3306/myc_test?useUnicode=true&characterEncoding=utf8&useSSL=true";
String username="root";
String password="MsQ3Ly%sy";
```
数据库用户名和密码直接硬编码在源代码中，一旦代码泄露，数据库安全完全丧失。

### 4.2 中等安全风险

#### 4.2.1 缺乏访问控制
**风险等级**：⭐⭐⭐ (中危)

**存在位置**：所有Servlet和JSP页面

**漏洞分析**：
- 没有实现基于角色的访问控制 (RBAC)
- 所有功能对所有"登录"用户开放
- 没有验证用户是否已登录，直接访问功能URL可能绕过登录

**攻击场景**：
- 攻击者直接访问`/add`、`/delstu`等URL，可能绕过登录页面
- 普通用户可以执行管理员操作（如删除学生）

#### 4.2.2 输入验证不足
**风险等级**：⭐⭐⭐ (中危)

**存在位置**：所有Servlet

**漏洞分析**：
- 没有对用户输入进行有效验证
- 没有检查输入长度、格式、范围
- 可能导致：
  - 数据格式错误（如日期格式不正确）
  - 缓冲区溢出（虽然Java有边界检查，但固定大小数组可能越界）
  - 业务逻辑错误（如负数的学号）

#### 4.2.3 会话管理问题
**风险等级**：⭐⭐⭐ (中危)

**存在位置**：
- `LoginAdminServlet.java`
- 所有使用session的Servlet

**漏洞分析**：
1. **会话固定攻击**：没有在登录后生成新的会话ID
2. **会话超时**：没有设置合理的会话超时时间
3. **敏感信息存储**：密码等敏感信息存储在会话中
4. **没有登出功能**：没有实现用户登出机制，无法主动销毁会话

### 4.3 低风险安全问题

#### 4.3.1 错误信息泄露
**风险等级**：⭐⭐ (低危)

**存在位置**：所有异常处理代码

**漏洞分析**：
```java
catch (SQLException e) {
    e.printStackTrace();
}
```
- 异常堆栈跟踪直接打印到控制台
- 可能泄露数据库结构、表名、字段名等敏感信息
- 虽然不在前端显示，但可能被日志记录

#### 4.3.2 缺少CSRF防护
**风险等级**：⭐⭐ (低危)

**存在位置**：所有表单提交

**漏洞分析**：
- 所有表单没有CSRF令牌
- 攻击者可以构造恶意链接，诱导已登录用户执行操作
- 例如：构造删除学生的链接，通过社交工程诱导管理员点击

#### 4.3.3 密码传输不安全
**风险等级**：⭐⭐ (低危)

**存在位置**：
- `login.jsp`
- `LoginAdminServlet.java`

**漏洞分析**：
- 登录表单使用GET方法提交：
```html
<form action="${pageContext.request.contextPath}/login" method="get">
```
- 密码会出现在URL中，可能被浏览器历史、服务器日志记录
- 没有使用HTTPS加密传输

### 4.4 安全风险汇总表

| 风险类型 | 风险等级 | 存在位置 | 可能影响 |
|---------|---------|---------|---------|
| SQL注入 | 严重 | JDBCemo, 多个Servlet | 数据泄露、数据篡改、数据库被完全控制 |
| 身份验证缺失 | 严重 | LoginAdminServlet | 未授权访问，任何人可进入系统 |
| 敏感信息明文存储 | 高危 | LoginAdminServlet, JDBCemo | 密码泄露、数据库凭据泄露 |
| 缺乏访问控制 | 中危 | 所有组件 | 越权操作、权限提升 |
| 输入验证不足 | 中危 | 所有Servlet | 数据异常、业务逻辑错误 |
| 会话管理问题 | 中危 | 所有使用session的组件 | 会话劫持、身份冒用 |
| 错误信息泄露 | 低危 | 异常处理代码 | 信息泄露、辅助攻击 |
| 缺少CSRF防护 | 低危 | 所有表单 | 诱导用户执行操作 |
| 密码传输不安全 | 低危 | 登录功能 | 密码被日志记录 |

## 五、代码质量与改进建议

### 5.1 代码质量问题

#### 5.1.1 数据库连接管理
**问题**：
- 使用单例模式但每次操作后关闭连接，可能导致并发问题
- 使用`DriverManager`而非连接池，性能差
- 连接信息硬编码，不可配置

**改进建议**：
1. **使用连接池**：
```java
// 建议使用HikariCP或Tomcat JDBC Pool
DataSource dataSource = new HikariDataSource(config);
try (Connection conn = dataSource.getConnection();
     PreparedStatement stmt = conn.prepareStatement(sql)) {
    // 执行操作
}
```

2. **外部化配置**：
```properties
# db.properties
jdbc.url=jdbc:mysql://localhost:3306/myc_test
jdbc.username=root
jdbc.password=your_password
```

#### 5.1.2 SQL注入防护
**问题**：
- 使用`Statement`而非`PreparedStatement`
- SQL字符串拼接

**改进建议**：
```java
// 原代码（危险）
String sql="select id from major where name="+"'"+major+"'"+";";
statement.executeQuery(sql);

// 改进代码（安全）
String sql = "SELECT id FROM major WHERE name = ?";
try (PreparedStatement pstmt = connection.prepareStatement(sql)) {
    pstmt.setString(1, major);
    ResultSet rs = pstmt.executeQuery();
}
```

#### 5.1.3 身份验证机制
**问题**：
- 没有实际的身份验证
- 密码明文存储和传输

**改进建议**：
1. **实现完整的登录验证**：
```java
// 从数据库验证用户
String sql = "SELECT password FROM users WHERE username = ?";
try (PreparedStatement pstmt = connection.prepareStatement(sql)) {
    pstmt.setString(1, username);
    ResultSet rs = pstmt.executeQuery();
    if (rs.next()) {
        String storedPassword = rs.getString("password");
        // 验证密码（建议使用哈希）
        if (verifyPassword(password, storedPassword)) {
            // 登录成功
        }
    }
}
```

2. **密码哈希存储**：
```java
// 使用BCrypt或PBKDF2进行密码哈希
String hashedPassword = BCrypt.hashpw(password, BCrypt.gensalt());
// 验证
boolean isMatch = BCrypt.checkpw(inputPassword, storedHash);
```

#### 5.1.4 会话管理
**问题**：
- 会话固定攻击风险
- 没有登出功能
- 敏感信息存储在会话中

**改进建议**：
1. **登录后创建新会话**：
```java
// 使旧会话失效，创建新会话
request.getSession().invalidate();
HttpSession newSession = request.getSession(true);
// 存储用户信息（不存储密码）
```
